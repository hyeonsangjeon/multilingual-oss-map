# Methodology & limitations

`multilingual-oss-map` is an interactive **language map of multilingual open source**, built from the
[GitHub Multilingual Repositories Dataset](https://github.com/github/multilingual-repositories)
(CC0‑1.0). This document explains exactly what the numbers are, how they are produced, and — just as
important — what they are **not**.

## 1. The source data

- **Dataset:** GitHub Multilingual Repositories Dataset (`github/multilingual-repositories`), released
  under **CC0‑1.0** (public domain).
- **Scale:** **80,657,333** classification rows across **40,817,528** distinct public repositories
  (snapshot day **2026‑05‑01**). Verified locally with DuckDB against the dataset's own README totals
  — see [`schema-notes.md`](schema-notes.md).
- **Three text sources**, never merged: the **README**, the **most‑commented issue**, and the
  **most‑commented pull request** of each repository.
- **Three classifiers**, kept separate: **fastText**, **gcld3**, and **lingua‑py**.
- Each classification is a `(repository_id, source, classifier, lang_code, confidence)` row with
  **confidence > 0.5**. The dataset contains **only non‑English** classifications, so English is
  absent by construction (see §4).
- Labels come from roughly the **first 150 characters** of each text.

## 2. How we aggregate (`scripts/aggregate.py`)

1. Read every parquet shard (the shards are grouped by source, so all must be scanned).
2. Deduplicate to the consensus grain **(repository, source, language)** and count how many
   **distinct classifiers** agreed, using `COUNT(DISTINCT classifier)` — the source shards contain
   repeated and exactly‑duplicated rows, so a naive `COUNT(*)` would over‑count.
3. This "agreement count" `k ∈ {1, 2, 3}` is the **strictness**. All rankings are **cumulative**:
   strictness *k* means "at least *k* classifiers agreed". So a repo counted at "all 3" is also
   counted at "≥2" and "≥1".
4. Emit small, deterministic JSON (`site/data/*.json`): per‑source language totals, per‑language
   detail (agreement split, primary repo language, star/fork quantiles), and per‑year time series.

The pipeline writes **no wall‑clock time** into its output, sorts every array, and uses integer
quantiles, so re‑runs are **byte‑identical** (checked with `sha256sum`). Every number on the site is
regenerated by this script; nothing is hand‑entered.

## 3. The strictness dial — the honesty control

Strictness is surfaced as a first‑class control instead of being hidden:

| Setting | Meaning | Character |
| --- | --- | --- |
| ≥1 | any one classifier | broad recall, noisiest |
| 2‑of‑3 | two agree (**default**) | balanced |
| all 3 | unanimous | high precision |

**Why it matters:** gcld3 and lingua‑py over‑fire on CJK scripts (each labels several million READMEs
as Chinese, versus fastText's ~221k), so **Chinese, Japanese and Korean move the most** as you turn
the dial. GitHub's own published aggregate tables correspond to our **all‑3** (unanimous) counts, and
match within ~0.01–1 % for PT/ES/RU/KO/TR/ID/ZH/JA — we use this as a correctness check (decisions
D6/D7). French and German differ more (~12 %/17 %), likely due to related‑language handling in the
published aggregate; this is documented as a known discrepancy, not silently reconciled.

## 4. Hard constraints (things this project deliberately does **not** do)

- **A language map, not a country map.** A region is shaded by the language most repositories there
  are classified in. It never asserts that those repositories are hosted, owned, or authored in that
  country. See the region method and its limits in
  [`language-region-mapping.md`](language-region-mapping.md).
- **Not ground truth.** Counts are always "repositories **classified as** language X", never
  "repositories that **use** X". Short text snippets capture badges, templates, install commands, and
  code‑switching.
- **No inference about people.** The data must not be used to infer the nationality, ethnicity,
  location, or any personal attribute of the humans behind a repository.
- **English is excluded, not zeroed.** Because the source contains no English rows, we show no
  English share and invent none. The map is explicitly *non‑English*.
- **The three sources are never collapsed** into a single "language of the repo".

## 5. Reading the specific views

- **Choropleth colour** is a colour‑blind‑safe Viridis **log** scale spanning the currently shaded
  min–max counts (decision D8). It encodes count magnitude only; hue carries no categorical meaning.
- **Asymmetry (slope) chart** links a language's README rank to its issue rank. The gap — not the
  absolute position — is the point. It is sharpest at higher strictness.
- **Star / fork figures are medians and high percentiles**, because the distribution is extremely
  long‑tailed: for most languages at least half of the repositories have **0 stars**.
- **Time series** counts repositories by **creation year**. Recent years (especially the
  2026 snapshot column) are **undercounted** — a young repository has fewer issues and PRs to
  classify — so read the shape, not the final step down.

## 6. Reproduce

```bash
bash scripts/download_data.sh     # raw parquet shards (~1.1 GB, git-ignored)
python3 scripts/aggregate.py      # rebuild site/data/*.json (deterministic)
python3 scripts/build_regions.py  # rebuild language→region mapping
cd site && npm ci && npm run build
```
