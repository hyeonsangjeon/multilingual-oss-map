> **프로젝트 스펙 / 에이전트 실행 지시서**
> GitHub Multilingual Repositories Dataset을 인터랙티브 세계지도 대시보드로 시각화한다.
> **대상 실행자**: Copilot(Opus) 에이전트 모드 / Claude Code
> **작성일**: 2026-07-25

## 0. 이 문서 사용법

이 문서를 에이전트에 그대로 전달하고 아래 한 줄을 덧붙인다:

> 이 스펙대로 PHASE 0부터 끝까지 자율로 완주해. 중간 확인 없이 진행하고,

그대로 코드에 박지 말 것.

## 1. 프로젝트 개요

### 무엇을 만드나

공개된 GitHub Multilingual Repositories Dataset(CC0-1.0)을 집계해,
**"오픈소스 협업이 어떤 언어로 이뤄지는가"**를 보여주는 정적 웹 대시보드.
GitHub Pages에 배포하는 단일 정적 사이트다.

### 왜 만드나 — 핵심 서사

이 사이트가 던지는 질문은 하나다:

> **개발자는 문서는 영어로 쓰고, 대화는 모국어로 한다?**

GitHub 발표에 따르면 **한국어는 이슈 텍스트에서 가장 흔한 비영어 언어인데,
README에서는 5위**다. 반대로 **포르투갈어는 비영어 README 1위(300만+ 레포)**다.
이 **비대칭(asymmetry)이 이 프로젝트의 중심 발견**이며, 모든 시각화는 이 축을
중심으로 배치한다. 단순히 "언어별 레포 수"를 그리는 지도는 이미 흔하다.
**"공식 문서 언어 vs 실무 대화 언어의 괴리"**가 이 사이트만의 앵글이다.

### 성공 기준

- 사이트를 30초 보고 나면 "아, 문서는 영어인데 대화는 모국어구나"가 이해된다
- 지도 위 어느 나라를 눌러도 그 언어권의 README/이슈/PR 비대칭이 즉시 보인다
- 모든 수치는 원본 데이터셋에서 재현 가능하며, 집계 스크립트가 레포에 있다
- 모바일에서도 읽힌다

## 2. 데이터 소스

- **데이터셋**: GitHub Multilingual Repositories Dataset
- **위치**: `github/multilingual-repositories` (GitHub)
- **라이선스**: CC0-1.0 (퍼블릭 도메인 — 재사용·재배포 자유)
- **규모**: 4,000만+ 레포에 걸친 8,000만+ 분류 행
- **배포 형태**: parquet 샤드 + 스키마 정의 + 집계 테이블(레포 문서 참조)

### 알려진 필드 (블로그 발표 기준 — 실제 컬럼명은 PHASE 1에서 확인)

**언어 분류 (텍스트 소스 3종)**
- README / 가장 댓글 많은 이슈 / 가장 댓글 많은 PR
- 각 텍스트의 **앞 150자**를 입력 샘플로 사용, 20자 미만 텍스트는 제외
- 분류기 3종 각각의 결과 + confidence score: **fastText / gcld3 / lingua-py**
- **confidence > 0.5인 분류만 수록**

**레포 메타데이터**
- creation timestamp, disk usage, stars, forks
- primary programming language, SPDX license
- issue count, pull request count, snapshot date

## 3. 반드시 지킬 원칙 (Hard constraints)

이 프로젝트는 데이터셋 발행자가 명시한 사용 제한이 있다. **위반 시 프로젝트 폐기 수준의 문제**다.

### 3.1 언어 ≠ 국가 (가장 중요)

지도를 그리는 순간 이 함정에 빠진다. 반드시:

- 이 사이트는 **"언어 지도"이지 "국가 지도"가 아니다.** 사이트 곳곳에 이를 명시한다.
- 스페인어 → 스페인 하나에 칠하면 **틀렸다**. 중남미 전역이 스페인어권이다.
  포르투갈어도 마찬가지(브라질이 압도적).
- **언어→지역 매핑 테이블(`lang-regions.json`)을 별도 파일로 만들고,
  매핑 근거와 한계를 그 파일 주석/문서에 남긴다.** 하드코딩 금지.
- 한 언어가 여러 지역에 매핑되면, 지도에서는 **해당 지역 전체를 같은 값으로 칠하되
  "이 색은 언어 사용 지역이지 레포 소재지가 아님"을 범례에 명시**한다.
- 영어는 전 세계라 지도로 의미가 없다 → **영어는 지도에서 제외하고
  "비영어 지도"임을 제목에 넣는다.** (별도 카드로 영어 비중만 표기)

### 3.2 사람 속성 추론 금지

데이터셋은 **"레포 소유자·기여자·커뮤니티의 민감 속성을 추론하는 데 사용하지 말 것"**을
명시한다. 따라서:

- **"○○국 개발자는 ~하다"** 식 서술 **전면 금지**
- 항상 **"이 언어로 분류된 레포는 ~"** 형태로만 서술
- 개인·조직 단위 분석, 랭킹, 지목 금지

### 3.3 Ground truth 아님

데이터셋은 **언어 식별의 정답 벤치마크가 아니라 발견용 도구**다.
- 사이트에 **"이 데이터의 한계" 섹션을 반드시 포함**한다
- 한계: 150자 샘플, 짧은 텍스트, 배지·템플릿·설치 커맨드·코드 조각 혼입,
  혼합 언어, 저자원 언어에서 분류기 편차
- 수치는 **"~로 분류된 레포 수"**이지 "~어를 쓰는 레포 수"가 아니다

### 3.4 분류기 3종을 뭉개지 않는다

데이터셋이 의도적으로 3개 분류기를 분리해 제공한다. 이 설계를 존중한다:
- **기본 집계 기준: 3개 분류기 중 2개 이상 일치(2-of-3 합의)** — 균형점
- UI에 **엄격도 토글** 제공: `1개 이상(넓은 재현율)` / `2개 이상(기본)` / `3개 모두(고정밀)`
- 토글을 바꾸면 지도와 차트가 즉시 갱신된다 → 사용자가 정밀도/재현율을 직접 조절
- 이 토글이 이 사이트의 **정직성을 보여주는 장치**다. 눈에 띄게 배치할 것.

## 4. 화면 구성 (Information Architecture)

단일 페이지 스크롤 + 인터랙션. 위에서 아래로 서사가 흐른다.

### ① 히어로 — 질문 던지기
- 큰 문장: "개발자는 문서를 영어로 쓰고, 대화는 모국어로 한다?"
- 부제: 4,000만+ 공개 레포의 README·이슈·PR 언어 분류로 확인한 것
- 핵심 수치 3개 카드: 총 레포 수 / 비영어 README 1위 언어 / 비영어 이슈 1위 언어
- **엄격도 토글**을 여기 배치 (아래 모든 시각화에 전역 적용)

### ② 메인 — 인터랙티브 세계지도 (코로플레스)
- 비영어 언어별 레포 수를 언어권 지역에 매핑해 색 농도로 표현
- **텍스트 소스 전환 탭: `README` / `Issues` / `Pull Requests`**
  → 탭을 바꾸면 지도 색 분포가 **눈에 띄게 달라진다.** 이게 이 사이트의 하이라이트.
  전환 시 부드러운 트랜지션으로 변화를 체감하게 할 것.
- 지역 hover: 언어명, 레포 수, 세 소스에서의 순위
- 지역 click: 아래 ③ 상세 패널로 스크롤 + 해당 언어 선택
- 범례에 "언어 사용 지역 표시이며 레포 소재지가 아님" 명시

### ③ 비대칭 차트 — 이 프로젝트의 핵심
- **덤벨/기울기 차트(slope chart)**: 언어별로 README 순위 ↔ 이슈 순위를 선으로 연결
- 순위가 크게 뒤집히는 언어(한국어 등)가 시각적으로 튀도록 강조
- 정렬 옵션: 비대칭 크기순 / README 순위순 / 이슈 순위순
- 캡션에서 한국어·포르투갈어 사례를 명시적으로 해설

### ④ 언어 상세 패널
- 선택된 언어 하나에 대해:
  - 세 소스별 레포 수와 순위
  - 분류기 3종의 합의 정도(1개만/2개/3개 모두 일치 비율) — 신뢰도 감각 제공
  - 해당 언어 레포의 주요 프로그래밍 언어 분포 (top 5)
  - 스타/포크 분포 요약 (중앙값 등 — 평균은 롱테일에 왜곡되므로 중앙값 우선)

### ⑤ 시계열 — 비영어 오픈소스는 늘고 있나
- creation timestamp 기준, 연도별 비영어 레포 생성 추이 (언어별 스택 영역 또는 라인)
- 상위 8개 언어 + 나머지 묶음
- 주의: 스냅샷 시점 편향(최근 레포일수록 이슈·PR이 적어 분류 누락 가능) 캡션에 명시

### ⑥ 방법론과 한계
- 집계 방식, 엄격도 정의, 언어→지역 매핑 방식과 그 한계
- §3의 제한 사항 전부 서술
- 원본 데이터셋 링크, CC0 표기, 집계 스크립트 링크
- 재현 방법: "이 사이트의 모든 수치는 `scripts/aggregate.py`로 재생성 가능"

## 5. 기술 스택과 아키텍처

### 원칙
**빌드 타임에 무거운 집계를 끝내고, 런타임에는 작은 JSON만 로드한다.**
브라우저에서 8,000만 행을 다루려 하지 말 것. 정적 호스팅에서 돌아가야 한다.

### 파이프라인

```
[원본 parquet 샤드]
        │
        ▼  scripts/aggregate.py  (DuckDB, 로컬/CI 1회 실행)
        │
        ▼
[집계 JSON — 수백 KB 수준]
   site/data/*.json
        │
        ▼  정적 사이트 빌드
        │
        ▼
[GitHub Pages]
```

### 스택
- **집계**: Python + **DuckDB** (parquet 직접 쿼리, 메모리 효율 좋음)
- **지도 렌더링**: **D3.js** + TopoJSON (world-atlas). geo projection은 자연스러운
  Natural Earth 계열 사용 (Mercator는 고위도 왜곡이 커서 부적합)
- **차트**: D3 또는 **Observable Plot** (덤벨/기울기 차트는 Plot이 간결)
- **프레임워크**: **바닐라 + Vite** 권장. React를 쓸 이유가 없는 규모다.
  단, 상태(엄격도·소스탭·선택언어)가 여러 컴포넌트에 걸치므로 작은 상태 스토어 하나 둘 것.
- **호스팅**: GitHub Pages (정적)

### 산출 데이터 파일 설계 (예시 — 실제 스키마 확인 후 조정)

```
site/data/
├── meta.json              # 스냅샷 날짜, 총 레포 수, 생성 시각, 데이터셋 버전
├── lang-totals.json       # [{lang, source, strictness, repo_count, rank}]
├── lang-detail.json       # 언어별 분류기 합의 분포, 프로그래밍 언어 top5, 스타 중앙값
├── timeseries.json        # [{year, lang, count}]
└── lang-regions.json      # 언어 → ISO 국가코드 배열 매핑 (근거 주석 포함)
```

`strictness`는 1/2/3 세 값을 모두 미리 계산해 담는다 (런타임 재계산 없이 토글).

## 6. 실행 계획 (PHASE)

각 PHASE 완료 시 커밋하고 **멈추지 말고 다음으로 진행**한다.

### PHASE 0 — 레포 스캐폴드
- 새 레포 `polyglot-commit` (또는 기존 레포 하위 디렉터리) 초기화
- 구조: `scripts/`, `site/`, `site/data/`, `docs/`(빌드 산출물 → Pages)
- README 초안, LICENSE(코드는 MIT), 데이터 출처·CC0 명시
- `.gitignore`에 원본 parquet 제외 (용량이 크므로 커밋 금지)
- 커밋: `chore: scaffold project`

### PHASE 1 — 데이터 확보와 스키마 확인 ⚠️ 추측 금지
1. `github/multilingual-repositories` 레포의 README와 스키마 정의 문서를 **직접 읽는다**
2. 실제 컬럼명·파일 배치·parquet 샤드 구조를 확인해 `docs/schema-notes.md`에 기록
3. 데이터 일부(샤드 1개)를 받아 DuckDB로 열어 실제 값 분포를 확인
4. 레포가 제공하는 **집계 테이블(aggregate tables)이 있으면 그것부터 활용**한다 —
   전체 샤드를 다 돌 필요가 없을 수 있다
5. 이 단계 결과에 따라 §5의 데이터 파일 설계를 조정한다
- 커밋: `docs: record dataset schema and access notes`

### PHASE 2 — 집계 스크립트
- `scripts/aggregate.py` 작성. 요구사항:
  - DuckDB로 parquet 직접 쿼리 (전체를 메모리에 올리지 않음)
  - 엄격도 1/2/3 각각에 대해 언어×소스별 집계
  - 시계열, 언어 상세(분류기 합의·프로그래밍 언어·스타 중앙값) 집계
  - 결과를 `site/data/*.json`으로 출력
  - **멱등성**: 같은 입력이면 같은 출력. 재실행해도 결과 동일
  - 실행 시간과 처리 행 수를 stdout에 로그
- `scripts/README.md`에 실행법과 소요 시간 기록
- 커밋: `feat: add aggregation pipeline`

### PHASE 3 — 언어→지역 매핑
- `site/data/lang-regions.json` 작성
- 상위 30개 비영어 언어를 커버. 각 언어에 ISO 3166-1 alpha-3 국가코드 배열 매핑
- **각 매핑에 근거를 주석 또는 별도 문서로 남긴다** (공용어/주요 사용 지역 기준)
- 매핑 불가/모호한 언어(예: 아랍어·스페인어처럼 광범위)는 그 사실을 데이터에 플래그로 표시
- `docs/language-region-mapping.md`에 방법론과 한계 서술
- 커밋: `feat: add language-to-region mapping with provenance`

### PHASE 4 — 지도와 차트 구현
- Vite 프로젝트 셋업, D3 + TopoJSON
- ②지도 → ③비대칭 차트 → ④상세 패널 → ⑤시계열 순으로 구현
- 전역 상태: `{ strictness, source, selectedLang }`
- 소스 탭 전환 시 지도가 **부드럽게 트랜지션** (변화를 체감하게 하는 게 핵심)
- 커밋: PHASE 단위가 아니라 컴포넌트 단위로 나눠 커밋

### PHASE 5 — 디자인
- **다크 테마 기본.** 데이터 시각화는 어두운 배경에서 색 대비가 잘 산다
- 코로플레스 색상: **순차형(sequential) 스케일**, 색맹 안전한 팔레트 사용
  (viridis/cividis 계열 권장. 무지개 스케일 금지 — 지각적으로 왜곡됨)
- 타이포: 본문은 가독성 좋은 산세리프, 수치는 tabular numerals
- **모바일**: 지도는 축소되면 읽기 어려우므로, 좁은 화면에서는
  지도 대신 **가로 막대 랭킹**으로 자동 대체(graceful degradation)
- 로딩 상태와 빈 상태를 반드시 처리

### PHASE 6 — 문서와 배포
- README: 프로젝트 소개, 스크린샷, 재현 방법, 데이터 출처와 라이선스
- `docs/methodology.md`: 집계 방식·엄격도·매핑·한계 전부
- GitHub Actions로 Pages 배포 워크플로
- 사이트 ⑥섹션이 이 문서들과 링크로 연결되는지 확인
- 커밋: `docs: methodology and deployment`

## 8. 판단 우선순위 (모호할 때)

에이전트가 스스로 결정할 때 이 순서로 판단한다:

1. **§3 Hard constraints** — 데이터셋 사용 제한. 무조건 최우선
2. **정직성** — 불확실하면 불확실하다고 표시. 예쁜 그래프보다 정확한 캡션
3. **성능** — 정적 호스팅에서 빠르게 뜨는가. 무거우면 집계를 더 줄인다
4. **서사** — README/이슈 비대칭이 드러나는가
5. **미감** — 위 넷을 해치지 않는 선에서

**확신이 없으면 만들지 말고, 만들었으면 한계를 적어라.**
